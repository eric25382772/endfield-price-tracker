讀懂陌生專案 — 小抄

指令記不住是正常的。觀念記住就好，指令複製貼上。

一、只要記住這三句

1. 檔案大小 ≠ 重要性

最小的 config.py（3 KB）是地基，誰都需要它。大只代表「寫了很多」。

2. 沒人 import 你 = 你是入口

被很多人 import 的是「零件／地基」；一次都沒被 import 的 .py，就是直接拿來跑的入口檔。

3. 工具跑出來的結果要先懷疑

用你已知的事實去對答案。已知 config 是核心，結果裡卻沒有 → 是工具壞了，不是 config 不重要。這叫 sanity check。

二、拆解陌生專案的五步

  1. 先看外觀，不開 code檔案清單、大小、資料夾名字。分出「程式 / 文件 / 產物」。
  2. 找入口程式從哪一行開始跑。用 import 統計找「沒被 import 的 .py」。
  3. 挑一個功能，追到底（tracing）主菜。80% 的時間花這。中間看到不懂的先標記，不要繞路。
  4. 畫出你自己的地圖寫下來，不要記在腦裡。
  5. 有疑問才回頭翻永遠不主動從頭讀到尾。沒有人這樣做。
核心心法：不要用讀的，要用查的。
帶著問題去找答案，找到就停。

三、指令小抄（複製貼上用）

列出所有檔案，由大到小

Get-ChildItem g:\project -File | Sort-Object Length -Descending | Select-Object Name, Length
段落作用
Get-ChildItem -File列出檔案，不要資料夾
Sort-Object Length -Descending照大小由大到小排
Select-Object Name, Length只顯示名字和大小兩欄
|pipe：把左邊結果餵給右邊

統計誰被 import 最多次 找地基

Select-String -Path g:\project\*.py, g:\project\ocr\*.py, g:\project\data\*.py -Pattern "^(?:from|import)\s+([\w.]+)" |
  ForEach-Object { $_.Matches[0].Groups[1].Value } |
  Group-Object | Sort-Object Count -Descending | Select-Object Count, Name -First 20
段落作用
^正規表達式：行首。避開註解裡的 import
([\w.]+)capture group（捕捉群組）：這一段單獨抓出來
$_.Matches[0].Groups[1].Value把捕捉到的模組名取出
Group-Object一樣的歸一組，順便數個數
這行指令的已知漏洞：因為用 ^ 卡行首，寫在函式裡面（有縮排）的 import 會被漏掉。 Python 允許 def main(): 底下再寫 import xxx。

四、看到一行 code，怎麼分辨誰是誰

while f2_pending_lock.is_set():
    time.sleep(0.3)
字誰的說明
whilePython 關鍵字跟 C / Java 一樣
f2_pending_lock作者自己取的改叫 abc 也能跑
.is_set()Python 標準庫threading.Event 的方法
time.sleep()Python 標準庫暫停幾秒
判斷法

名字在描述這個專案特有的東西（f2、friend、region、quota）→ 作者取的。
名字很通用（get、set、sleep、append、open）→ 通常是 Python 的。

五、名詞表

詞白話
執行緒 thread同一個程式裡的分身。彼此共用記憶體，看得到對方的變數
行程 process完全獨立的程式。看不到對方的變數，要溝通得靠檔案或網路
佇列 queue排隊的籃子。一邊丟一邊撿，先進先出
阻塞 blocking「卡在這裡等」，等到有東西才往下走
Event（旗子）只有開／關的燈號。.set() 開、.clear() 關、.is_set() 問亮不亮
tracing挑一個使用者動作，從頭跟到尾，看資料流過哪些地方
sanity check合理性檢查。用已知事實驗證工具的輸出對不對
f-stringf"你好 {name}"，跟 PHP 的 "你好 $name" 一樣
標準庫Python 內建、不用安裝的模組：os、re、json、time…
